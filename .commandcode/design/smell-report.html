// TL;DR

The interface is not generic; it is under-designed at the edges. The transcript vocabulary is specific and deliberate: ❯ for tool commands, dim for output, reverse-video for the live menu, a 10-row window with ↑/↓ N more hints, ghost rows wiped on backspace and Esc. The copy has a voice. What is missing is a model of the window it runs in, a role system for color, and a type scale for model output.

Fix in this order: give the prompt and menu a size model (interaction/relayout), then color roles (recolor), then the markdown scale (typeset).

// WHAT'S WORKING

The live menu belongs to this brief

A 10-row window that scrolls around the selection with ↑/↓ N more hints, reverse-video selection, and surplus rows blanked on backspace or Esc so a closing menu never leaves ghosts. Verified clean at 100×30 and covered by sequence-level tests.

Copy with a voice

"… 12 more lines (full output sent to model)", "gone: set it inline now — /provider <name> key=<key>", "stopped (Esc)", "no key entered — set it later". Instruction-first, no filler, no exclamation points.

TTY discipline

Raw mode is a guard that restores on drop, errors go to stderr, and styling disappears when stdout is not a TTY — so the same binary is a clean pipe target.

P1 · MEDIUM · COLOR

Eight codes carry twelve jobs, so severity is decided per call site

src/ui.rs:5-12, :22-34, :47, :232-266, :884; src/agent.rs:128. Yellow is both the missing-key warning and the tool echo, green is both the wordmark and the prompt mark, cyan is both info and inline code, dim is tool output, thinking, fences and the truncation notice. Failure news renders three ways: plain println!, cyan, red — "unknown command" plain, "usage: /rewind [n]" cyan, "no API key" red.

FIX: one role per code; give error and warning a glyph or word so severity survives without hue; route every message through a role instead of the bare println!.
P1 · MEDIUM · TYPE

Six heading levels, one treatment

src/ui.rs:113-116: hashes 1..=6 all map to style(BOLD, …), so #, ## and ### are indistinguishable. Model answers arrive with three-level heading trees and lose all of it.

FIX: map onto the media the terminal has — H1 bold + reverse, H2 bold, H3 bold dim, H4–6 dim.
P1 · MEDIUM · LAYOUT

The table renderer fabricates structure it does not have

src/ui.rs:101-108: rules are built from the source dashes (|​---​|---​| → ─── ───) and cells are joined with a fixed two spaces, so the rule never matches the column above it and no two rows align. The in-tree test asserts the fake rule verbatim (ui.rs:1213).

FIX: buffer a table block, size columns to content, pad cells, span rules across the column width — or drop per-column rules for one dim full-width rule.
P1 · MEDIUM · INTERACTION

The 12-line output cut hides the two lines that matter

src/ui.rs:238-256 shows the first 12 lines and summarizes the rest, but src/shell.rs:82 and :91 append [stderr] and [exit N] at the end of the payload — so for any command longer than 12 lines, the error block and the exit code are exactly what gets hidden.

FIX: show head and tail (e.g. 8 + 4) or always surface the trailer line; keep the "N more lines" notice.
P2 · LOW · INTERACTION

Bare /model promises navigation its static list does not have

src/commands.rs:122-158, src/agent.rs:128: the dump is headed "type to search, ↑↓ pick, Enter sets" — copy that describes the live menu. With a fetched OpenRouter catalog it is hundreds of rows of scrollback.

FIX: open the live menu on bare /model, prefilled with the current id — or cap the dump and say "refine with /model <fragment>".

src/agent.rs:465. compacting names its work; working names nothing.
